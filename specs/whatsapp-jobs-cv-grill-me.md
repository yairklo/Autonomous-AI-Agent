# סריקת משרות ב-WhatsApp והגשת קורות חיים — Grill-Me Spec

_סטטוס: אושר. נשלח ל-Cursor (ארכיטקטורה: MCP Tool מקומי)._

## היקף ומטרות

### primary-goal
**Q:** מה המטרה העיקרית: התראות בלבד, הגשות אוטומטיות, או שילוב (סריקה + הצעה + אישור + הגשה)?
**A:** שילוב: סריקה + ניתוח + התראה בטלגרם + מילוי טופס ב-Playwright לאחר אישור.

### success-metric
**Q:** איך נמדוד הצלחה בשבוע הראשון (מספר משרות שזוהו, הגשות, ראיונות, חיסכון בזמן)?
**A:** משרות Full Stack/Backend שזוהו, אישורי טלגרם, הגשות Playwright מוצלחות — ללא שליחות WhatsApp.

### out-of-scope
**Q:** מה במפורש מחוץ להיקף בגרסה הראשונה (לינקדאין, מייל, אתרי דרושים, בוטים אחרים)?
**A:** אין DMs/תגובות בוואטסאפ; אין שליחה לקבוצות; רק טפסים חיצוניים ב-Playwright.

## גישה ל-WhatsApp וקבוצות

### wa-client
**Q:** איך מתחברים ל-WhatsApp: WhatsApp Web / Baileys / API עסקי / ייצוא צ׳אט ידני / אחר?
**A:** whatsapp-web.js (האזנה בלבד). ייצוא .txt נתמך כנתיב בדיקות/גיבוי.

### target-groups
**Q:** אילו קבוצות לסרוק (רשימה קבועה, תגיות, כל הקבוצות, רק כאלה עם מילות מפתח בשם)?
**A:** קבוצות מוגדרות ב-config.json בלבד.

### scan-cadence
**Q:** מה קצב הסריקה (בזמן אמת, כל X דקות, פעם ביום) ומה חלון ההיסטוריה לסריקה ראשונה?
**A:** סריקה בזמן אמת.

### media-handling
**Q:** האם לנתח גם תמונות/PDF/הודעות קוליות של משרות, או טקסט בלבד ב-v1?
**A:** טקסט בלבד.

## זיהוי והתאמת משרות

### match-signals
**Q:** מה מסמן "משרה" (מילות מפתח בעברית/אנגלית, תבניות כמו "דרוש/ה", לינקים, מספרי טלפון)?
**A:** משרות Full Stack/Backend בעברית/אנגלית.

### relevance-filter
**Q:** איך מסננים רלוונטיות לפרופיל (תפקידים, סטאק, מיקום, היברידי/משרד, ותק, שכר מינימום)?
**A:** סינון לתפקידי Full Stack / Backend לפי config.json.

### dedupe
**Q:** איך מטפלים בכפילויות בין קבוצות ובמשרות שחוזרות עם ניסוח שונה?
**A:** סינון כפילויות ב-DB מקומי (fingerprint).

### languages
**Q:** באילו שפות המשרות והסוכן צריכים לעבוד (עברית, אנגלית, שתיהן)?
**A:** עברית ואנגלית.

## מבנה פרופיל מועמד

### profile-fields
**Q:** אילו שדות חובה בפרופיל (שם, תפקיד יעד, skills, שנות ניסיון, מיקום, זמינות, לינקים)?
**A:** שם, מייל, טלפון, לינקדאין, גיטהאב.

### cv-assets
**Q:** איפה נמצאים קבצי ה-CV (נתיב מקומי, כמה גרסאות לפי תפקיד/שפה, תבנית מכתב מקדים)?
**A:** assets/cv.pdf + תבניות מכתב מקדים בפרופיל / LLM.

### constraints
**Q:** מהם אילוצי סינון קשיחים (לא סטארטאפים, לא גיוס ביטחוני, לא שליחויות, ימי שלישי בלבד וכו׳)?
**A:** רק Full Stack/Backend; קבוצות מ-config.json בלבד.

### personalization
**Q:** האם להתאים אוטומטית מכתב מקדים / תקציר לכל משרה, או לשלוח CV קבוע?
**A:** מכתב מקדים מותאם ב-LLM (עם נפילה לתבנית).

## זרימת הגשה

### submit-channel
**Q:** לאן מגישים: תשובה באותה קבוצה, DM למפרסם, אימייל שחולץ מההודעה, טופס חיצוני, או הכל לפי זיהוי?
**A:** Playwright לטפסים בלבד (ללא DMs/תגובות בוואטסאפ).

### message-template
**Q:** מה תבנית הודעת ההגשה (טון, אורך, שפה, האם לצרף קובץ או לינק בלבד)?
**A:** מכתב מקדים מותאם + העלאת assets/cv.pdf בטופס.

### rate-limits
**Q:** מה מגבלות קצב בטוחות (הגשות ליום, השהייה בין הודעות) כדי לא להיחסם?
**A:** השהייה בין הגשות (config.json submission.delayBetweenSubmissionsMs).

### failure-handling
**Q:** מה קורה כשאין אימייל/מספר, כשההגשה נכשלת, או כשהמשרה כבר נסגרה?
**A:** התראה בטלגרם בכישלון; בלי URL לטופס — אין הגשה (אין WA fallback).

## אישורי אדם ו"סיום"

### who-approves
**Q:** מי מאשר הגשה: אתה בטלפון/טרמינל לכל משרה, אישור לפי כללים, או אוטומטי מעל ציון התאמה?
**A:** אישור חובה בטלגרם.

### approval-ux
**Q:** איך נראה אישור (כפתור ב-PWA, תשובת כן/לא בקול, פקודה ב-chat, digest יומי)?
**A:** כפתורי Approve/Reject בטלגרם.

### done-means
**Q:** מתי משימת "הגשה" נחשבת הושלמה (נשלח, נקרא, קיבלנו תשובה, נקבע ראיון)?
**A:** טופס Playwright מולא לאחר Approve ונשמר בלוג מקומי.

### audit-log
**Q:** איזה לוג/היסטוריה חובה לשמור (משרה מקור, ציון, מה נשלח, מתי, סטטוס)?
**A:** DB מקומי + חבילות תחת data/cv-applications.

## קריטריוני קבלה, פרטיות ובטיחות

### acceptance-v1
**Q:** מהם 3–5 קריטריוני קבלה ל-v1 שנוכל לבדוק ב-E2E או ידנית?
**A:** (1) סריקה לפי config.json (2) dedupe מקומי (3) Telegram Approve/Reject (4) Playwright רק אחרי Approve (5) אפס שליחות WhatsApp.

### privacy
**Q:** איפה מותר לאחסן הודעות קבוצה ו-CV (לוקאלי בלבד / הצפנה / מחיקה אחרי X ימים)?
**A:** אחסון מקומי בלבד.

### safety
**Q:** מה אסור לסוכן לעשות לעולם (שליחה לקבוצה בלי אישור, שיתוף CV מחוץ לרשימה, מענה לספאם)?
**A:** לעולם לא לשלוח הודעות בקבוצות WhatsApp ולעולם לא להגיש ללא אישור.

### stack-constraints
**Q:** האם הכלי חייב להיות MCP tool מקומי בסוכן הזה בלבד, או שירות נפרד?
**A:** MCP Tool מקומי המשולב בסוכן.
